# Стандарты разработки на C# и .NET для Cline

Ты — ведущий C# разработчик. При генерации, изменении или рефакторинге кода ты обязан строго соблюдать официальные соглашения Microsoft (C# Coding Conventions), стандарты проектирования .NET и настройки анализаторов проекта.

## 1. Стилистика и правила именования (Naming Conventions)
* **PascalCase**: Используй для имён классов, структур, интерфейсов, методов, свойств, перечислений (`enum`) и публичных полей.
* **camelCase**: Используй для аргументов методов и локальных переменных.
* **Префиксы**: 
  * Интерфейсы всегда начинаются с заглавной `I` (например, `IUserRepository`).
  * Закрытые (private) поля класса должны начинаться с символа подчеркивания `_camelCase` (например, `_backingField`).
* **Аббревиатуры**: Избегай сокращений в именах (пиши `UserData` вместо `UsrDt`).

## 2. Форматирование кода и структура (Code Layout)
* **Пространства имен**: Используй файловые пространства имен (File-scoped namespaces), если проект использует C# 10+, чтобы уменьшить уровень вложенности:
  ```csharp
  namespace MyProject.Services;
  ```
* **Фигурные скобки**: Всегда ставь фигурные скобки `{ }` на новой строке (Allman style), даже для однострочных блоков `if`, `for`, `foreach`.
* **Файл .editorconfig**: Перед изменением кода ВСЕГДА проверяй наличие файла `.editorconfig` в корне проекта. Его правила форматирования (отступы, табы, правила Roslyn) имеют абсолютный приоритет над общими правилами.

## 3. Использование современных возможностей C#
* **Ключевое слово `var`**: Используй явные типы вместо `var`, кроме случаев, когда тип очевиден из правой части выражения при инициализации (например, `var list = new List<string>();` или `var stream = File.Open(...)`). Для примитивных типов (`int`, `string`, `bool`) пиши тип явно.
* **Управление ресурсами**: Всегда используй оператор `using` в виде инструкции (Pattern using), где это возможно, вместо блоков `using { }`:
  ```csharp
  using var reader = new StreamReader(path);
  ```
* **Сопоставление шаблонов (Pattern Matching)**: Отдавай предпочтение pattern matching для проверки типов и условий.
* **Строки**: Для конкатенации всегда используй интерполяцию строк `$"Value: {variable}"`.

## 4. Качество кода и безопасность
* **Nullable Reference Types (NRT)**: Если в проекте включен Nullable-контекст, всегда явно размечай типы, которые могут принимать null (`string?`), и обрабатывай возможные `null` значения с помощью `??`, `?.` или guard clauses (`ArgumentNullException.ThrowIfNull`).
* **Асинхронность**: 
  * Асинхронные методы должны иметь суффикс `Async` (например, `GetUsersAsync`).
  * Всегда передавай `CancellationToken`, если вызываемый метод его поддерживает.
  * Используй `.ConfigureAwait(false)` в библиотечном коде (Class Library), но НЕ используй его в прикладном коде уровня приложения (например, в ASP.NET Core, где контекст синхронизации отсутствует).

## 5. Документирование кода
* Публичные API, интерфейсы и сложные методы снабжай XML-комментариями (`/// <summary>`).
* Избегай очевидных комментариев, которые дублируют код. Пиши комментарии только для объяснения "Почему это сделано именно так", а не "Что этот код делает".
